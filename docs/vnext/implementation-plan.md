See [characterization evidence](phase-1-characterization.md) and [final verification](verification.md). Plugin QA's monorepo source rule rejects this standalone layout; supplemental checks are recorded separately. Each phase updates this plan with actual results, versions, failures and remaining decisions. Use feature branches and PRs; tests precede changed behavior. Do not advance with unexplained baseline failures or certify a host from documentation alone.

## Release/coordination gate

Update README, current schema, platform guides, installer, copied skills/commands and changelog when behavior ships; this bootstrap only adds a planning link and Unreleased documentation entry. Review all staged files and privacy exclusions. Compatibility claims require evidence. Provide the wrapper a stable resolution/config/schema/proposal-exclusion contract after the relevant phase passes; do not let the wrapper define a competing resolver.

Open decisions: explicit root configuration mechanism/anchoring; manifest wire format; stable ID encoding and typed-relation serialization; queue behavior without a workspace; host versions and runtime verification availability. These are bounded phase decisions, not permission to relax required behavior.
