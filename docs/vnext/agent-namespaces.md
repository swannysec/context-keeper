# Agent memory, instruction, and skill namespaces

Verified 2026-10-06. This note records documented/source-inspected paths that matter to Context Keeper compatibility. It is not an integration certification: exact loading can depend on product version, launch directory, worktree, trust settings, and configuration. `.ai/` is Context Keeper's proposed portable convention; these sources do not establish that `.ai/` is globally reserved or collision-free.

## Current namespaces

| Agent | Native memory or session state | Project instructions and context | Skill discovery | Context Keeper implication |
|---|---|---|---|---|
| **Codex** | The official docs describe `AGENTS.md` as instruction context, not a dedicated automatic project-memory store. No native project memory path is established by the sources checked here. | `AGENTS.md` and `AGENTS.override.md` are read from repository root through the current directory; user instructions may be in `$CODEX_HOME/AGENTS.md` (normally `~/.codex/AGENTS.md`). | Current project skills use `.agents/skills/<skill>/SKILL.md`, discovered from the current directory through parents. User skills use `~/.agents/skills/`; admin skills use `/etc/codex/skills/`. The official installer example instead writes user-installed skills to `$CODEX_HOME/skills/` (normally `~/.codex/skills/`), a distinct installer location. | The existing Context Keeper Codex adapter and guide use project `.codex/skills/`. That does not match the current documented project-local Codex skill discovery path. Update the adapter in a later compatibility phase to `.agents/skills/` and verify full workflows; do not confuse it with the Codex installer’s user-skill destination. Keep Context Keeper memory under its own selected root. |
| **Claude Code** | Automatic project memory is stored under `~/.claude/projects/<project>/memory/` (including `MEMORY.md` and topic files); the exact project/worktree identity follows Claude Code's documented loader. It can be redirected with `autoMemoryDirectory`. This is distinct from project `.claude/memory/`. | Project instructions include `CLAUDE.md` and `.claude/CLAUDE.md`; user instructions include `~/.claude/CLAUDE.md`; `.claude/rules/*.md` supplies modular rules. User skills use `~/.claude/skills/<skill>/SKILL.md`. | Do not treat `.claude/memory/` as Claude Code's automatic-memory directory or commandeer native memory. Context Keeper's legacy fallback there is a historical project convention and must remain explicitly distinguishable. |
| **Google Antigravity** | The checked rules/skills documentation does not specify a separate native durable-memory directory. | Workspace instruction/rule sources include `AGENTS.md`, `GEMINI.md`, `.agents/AGENTS.md`, and `.agents/rules/*.md`; global rules include `~/.gemini/AGENTS.md` and `~/.gemini/GEMINI.md` (and documented rules locations). | Workspace `.agents/skills/<skill>/`; IDE global `~/.gemini/config/skills/`; CLI global `~/.gemini/antigravity-cli/skills/`. The docs retain `.agent/skills/` as a backward-compatible workspace path. | `.agents/` already has documented agent instruction and skill uses. That does not itself prove a conflict with `.ai/`; it does mean the namespaces must remain separate and tested in each product. |
| **Zed** | The checked Agent documentation does not specify an independent durable-memory store. | Project context can use `AGENTS.md`, `AGENT.md`, `CLAUDE.md`, or `GEMINI.md` according to its discovery rules. Discovery is direct-child based, and project skills require a trusted worktree. Zed documents that external agents use their own loaders. | Share portable instruction/skill content only where the host's loader supports it; do not infer that Zed's behavior applies to an external agent running in its terminal. | **Delta** | The inspected source documents Delta sessions/checkpoints separately; this namespace check makes no claim that these are Context Keeper memory. | Remote `main` recognizes project instruction names including `AGENT.md`, `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `.rules`, `.cursorrules`, `.windsurfrules`, `.clinerules`, and `.github/copilot-instructions.md`; global rule filenames include `AGENT.md` and `AGENTS.md`. The README describes `.agents/` as shared project agent configuration and `.delta/` as Delta-specific overrides. | Project skills are `.agents/skills/` and `.delta/skills/`; global skills are `~/.agents/skills/`. | Delta's current source supports the shared `.agents/skills/` location, while retaining a Delta-specific extension. This is evidence for a native adapter opportunity, not a cross-host compatibility certification. |
| **Hermes Agent** | Hermes owns native memory and session lifecycle. Current docs identify `~/.hermes/memories/MEMORY.md` and `USER.md`; native session storage/search and compaction remain Hermes-managed. Skills use `~/.hermes/skills/` and project skill discovery is separately documented. | Startup context selection is mutually exclusive by type: nearest `.hermes.md`/`HERMES.md` takes priority; otherwise an `AGENTS.md` chain; otherwise `CLAUDE.md`; otherwise Cursor rules. The AGENTS chain walks Git root to working directory, selecting the first nonempty `AGENTS.override.md`, `AGENTS.md`, or `agents.md` per directory. ## Limits and implementation checks

- `.ai/` is not established here as reserved by any of these agents. The absence of a documented collision is not proof that every present or future tool ignores it. Keep the path configurable where the compatibility design calls for it, and diagnose existing directories before initialization.
- The documentation is version-sensitive. In particular, Claude Code nested skill behavior has explicit version gates; Antigravity, Zed, and Codex docs may change independently of this snapshot.
- The Hermes source/docs disagreement is specific: its bundled skill reference says parent AGENTS files are ignored, while current `prompt_builder.py` and current feature docs describe root-to-working-directory AGENTS loading. Update or avoid relying on the stale reference when implementation begins.
- The existing Context Keeper Codex `.codex/skills/` adapter discrepancy is verified against current official Codex documentation, but this note does not change or certify the adapter. Phase 8 must exercise init, read, sync, search, and handoff using current supported discovery.
- No host is certified as compatible with the full Context Keeper workflow by this namespace inventory. Runtime versions, settings, symlink/worktree behavior, and end-to-end operations remain implementation verification items.
